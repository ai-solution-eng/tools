### P1-1 A documented admin endpoint returns 500 for 4 of its 5 group-by modes `[V]`
`src/pcai_llm/api/routes_admin.py:1989-2019`, twin at `src/pcai_llm/api/routes_team_leader.py:1046-1069`

```python
dims = {
    "key": "l.key_id, k.name AS key_name, k.key_prefix AS key_prefix",
    "tenant": "t.id AS tenant_id, t.name AS tenant_name",
    "day": "date_trunc('day', l.ts) AS day",
    "subject": "k.subject_id, s.subject AS subject, s.idp AS subject_idp, s.kind AS subject_kind",
}[group_by]
...
GROUP BY {dims}
```

The same `dims` string feeds both the SELECT list and `GROUP BY`, so `GROUP BY` receives `expr AS alias` items. PostgreSQL's `group_by_item` accepts only `a_expr`; `AS` is legal only in a target list. **Reproduced on a throwaway Postgres 16 instance:**

```
GROUP BY l.key_id, k.name AS key_name, k.key_prefix AS key_prefix;
ERROR:  syntax error at or near "AS"
```

`group_by=key|tenant|day|subject` → 500 on **both** `GET /admin/usage` and the team-leader usage rollup. `group_by=model` (no alias) works. Survives because the console only calls `/usage?limit=100` (`ui/admin.html:3635`) and every test runs against DB fakes.
**Fix:** split into `select_dims` (with `AS`) and `group_dims` (bare expressions), or `GROUP BY 1,2,…` ordinals. Add one real-Postgres test.

### P1-2 Concurrency-slot leak: the plain streaming branch sits outside both release paths `[V]`
`src/pcai_llm/api/routes_proxy.py:5526`, `:5506-5511`

```python
    except BaseException:
        # Slot-leak fix (security audit): EVERY post-gate raise must give back
        _release_in_flight(key.id)
        raise
    ...
    if bool(body.get("stream")):
        # Streaming: slot ownership TRANSFERS to the stream generator
        stream_resp = await _stream_chat(...)      # <-- OUTSIDE the guard
```

The `except BaseException` guards the relay branch only; the plain streaming dispatch at :5526 is bare. `_stream_chat` releases only on its own expected error paths, so a client disconnect during the up-to-45 s TTFT peek (`_peek_first_data_line` re-raises cancellation at :3174-3180, and the call site handles only `httpx2.HTTPError`) or an `await resp.aclose()` fault leaks the slot. The file's own comment at :2991 states the consequence: *"the _in_flight counter never decrements -> the key is 429-bricked on its concurrency cap until the pod restarts."*
**Fix:** make release idempotent (a once-wrapper) and wrap the whole post-gate body — relay **and** plain streaming — in `try/except BaseException`. Idempotence matters: `_stream_chat` already releases before raising its own 502, and a naive double release would decrement a concurrent request's slot.

### P1-3 `stream_once` re-picks a breaker-cooled endpoint `[V]`
`src/pcai_llm/api/routes_proxy.py:5157`

```python
p = pool_for or pool
ep2 = p.pick() or (p.endpoints[0] if p.endpoints else ep)
```

`Pool.pick()` returns `None` **precisely when every endpoint is cooling or probe-failed** (`routing/router.py:147-149`: `candidates = self.healthy(); if not candidates: return None`). This line then serves `endpoints[0]` anyway, ignoring the breaker, the priority tiers and `weight == 0` standby. `_decision_caller` documents this exact construct as the bug it removed (:653-658: *"The old `or pool.endpoints[0]` fallback re-picked a COOLING endpoint on every request"*). The relay is the dominant agent path and calls `stream_once` once per iteration, so a tripped breaker buys nothing.
**Fix:** `ep2 = p.pick()`; when `None`, yield an error event and let the relay's existing failover walk take the hop.

### P1-4 TPM cache refund is unbounded by the request's own admission charge `[V]`
`src/pcai_llm/core/budgets.py:1453-1455` + `:1253-1268`

```python
elif settings.rate_limit_exclude_cached_tokens:          # default TRUE
    await _refund_window_tokens(key_id, cached_tokens)
...
UPDATE rate_windows r SET tokens = GREATEST(r.tokens - $3, 0)
```

The admission charge is the **text-only** estimate (`routes_proxy.py:436-437`; the `tools` catalog and image parts contribute 0), while `cached_tokens` is the upstream's **real** prompt size, which includes tool schemas and images rendered by the chat template. On agent traffic a repeated request with a large tool catalog charges ~1k and refunds ~50k. The clamp bounds the refund against the *window balance*, not against what this request was charged — so the window drains to 0, `row["tokens"] > tpm` is never true, and **TPM stops enforcing for the rest of the minute**. Confirmed the refund path is the default: `rate_limit_exclude_cached_tokens = True` (config.py:141) while `rate_limit_predict_cached = False` (config.py:165), and `_remember_charge` is only called when prediction changed the charge (:957).
**Fix:** always `_remember_charge(request_id, charge)` at admission and refund `min(cached_tokens, remembered_charge)`.

### P1-6 Credit-card PII mask bypassed by dots, NBSP and zero-width separators `[V]` *(known-open since 2026-10-28)*
`src/pcai_llm/core/guardrails.py:131`

```python
_CARD_CANDIDATE_RE = re.compile(r"\b(?:\d[ -]?){13,19}\b")
```

Only space and hyphen are accepted separators. **Executed against the live module:**

| input | result |
|---|---|
| `4111 1111 1111 1111` | MASKED |
| `4111-1111-1111-1111` | MASKED |
| `4111.1111.1111.1111` (Luhn-valid, the most common card *display* format) | **LEAKED** |
| `4111\u00a01111\u00a01111\u00a01111` (NBSP) | **LEAKED** |
| `4111\u200b1111\u200b1111\u200b1111` (zero-width) | **LEAKED** |

The 10-28 audit flagged this; no later wave fixed it (the 11-02 wave touched only the EMAIL pattern).
**Fix:** widen the separator class to `[ .\-]`, strip zero-width characters before the candidate scan, keep the Luhn gate.

### P1-7 The "ONE hash walk per turn" optimisation is inert — every healthy relay turn walks the history three times `[V]`
`src/pcai_llm/api/routes_proxy.py:3889` + `src/pcai_llm/core/canonical.py:166-176, 216, 267`

```python
# canonical.py:166 — "Returns None the moment a mismatch is found ...
#                    a full pass means byte-identical prefix."
def prefix_hashes(canon, incoming) -> list[int] | None:
    ...
    return None                      # BOTH "matches" and "not computed"
```

`None` means both "prefix matches" and "not computed", and both callees recompute on `None`:
`mismatch = prefix_hashes(...) if prefix_verdict is None else prefix_verdict` (:216 and :267). The reset path early-exits at the first mismatch; the **extend** path — every healthy agent-loop turn — costs three full walks, each `json.dumps(message, sort_keys=True)` per message over the whole history, synchronously before the upstream call (TTFT).
**Fix:** reserve `None` for "not computed" and return `[]` for a clean prefix.

### P1-8 Default `/mcp` `tools/list` fans out to every granted server serially, 15 s each `[V]`
`src/pcai_llm/api/routes_mcp.py:1476-1487` (contrast :852-859)

```python
for server in await registry.mcp_servers():        # serial
    tools = await _cached_upstream_tools(server)   # _LISTING_TIMEOUT_S = 15.0
```

`mcp_flat_tools` defaults `True` (config.py:474), so this **is** the default discovery surface and the first call any MCP client makes. The catalog path was converted to a bounded concurrent gather (:852-859) — the flat path was left serial, bounding amplification but not latency: a cold cache with N servers costs up to N × 15 s, past most clients' 30-60 s timeout. Every admin MCP edit clears the cache fleet-wide, and a fresh pod starts cold.
**Fix:** reuse the `_mcp_catalog` semaphore+gather pattern.

## 5. SOLID — verified, do not "fix"

Per-request gates are genuinely fail-closed and the ordering contract holds on both surfaces (validation → rate → registry → ACL → arg policy → tool policy → upstream → settle). `require_admin`'s four-rung design enforces "a bad credential is never a downgrade". Key material is 32-byte `token_urlsafe`, SHA-256 at rest, never logged, no Python-side secret comparison. JWT rungs pin issuer/audience/algorithms-from-JWKS, re-verify before enforcing `azp`, and fail closed on infra errors. The `key_group` rotation-continuity fix is applied consistently across all three writers. `_window_start` is UTC-exact with atomic month+day replacement. The rate-window increment is one atomic `INSERT..ON CONFLICT..RETURNING`, and the refund never UPSERTs (no window resurrection). `costs.compute` uses Decimal with a finite-rate guard and `-inf` sentinel. `Pool.healthy()`'s never-empty invariant carries breaker **and** probe state across `replace_pools`. `decision_routing.parse_choice` abstains on non-finite confidence and refuses an unoffered choice. `routing_config`'s type-tagged encode/decode keeps the `bool("false")` P0 class closed. `response_cache` is PK-scoped per key — a tenant's answer can never be served to another. `clientside` caps pending per key, rejects replays and pops in `finally`. The health probe implements the full 2026-11-03 incident rule set. Container posture is real (non-root 10001, seccomp RuntimeDefault, drop ALL, readOnlyRootFilesystem, `automountServiceAccountToken: false`, all secrets by reference). `_fold` machinery is length-preserving with no ReDoS-capable nested quantifiers. `audit.py` redaction exemptions are all non-sensitive metadata and still recurse into nested values.

## 7. Feature-improvement themes

- **Unpriced models are free against every USD budget, forever.** A model with no `model_costs` row ledgers `cost_usd NULL`, and `SUM` ignores NULL — so a tenant with only a USD budget can burn unbounded GPU time on any newly registered model. Needs a startup/admin warning plus a fallback rate so the gate cannot be silently inert. `core/costs.py:53-57`; `core/budgets.py:320`
