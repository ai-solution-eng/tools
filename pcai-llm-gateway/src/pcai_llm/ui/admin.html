Model routing — what the router may use, and what the decision model is told

—
Runtime enabled — AND-ed with env PCAI_LLM_ROUTING_ENABLED, which owns the route mount. With Decision mode = off the shipped heuristics run exactly as before, gated on the env flag alone.
Decision mode
off never calls the decision model — the shipped heuristics alone pick the model. shadow calls the model and records what it WOULD have picked (ledger routing_would) while the heuristics still serve — the model’s choice never reaches the user, and each routed request pays one extra decision call (bounded by the timeout above). Use it to compare the model against real traffic. active serves the model’s choice when it clears the confidence floor and lands inside the candidate window; otherwise the heuristics serve.
Decision model decision-capable pool consulted for complex requests; empty = heuristics only
Confidence floor below this the model is treated as ABSTAINING and the heuristics serve. d3-turbo is calibrated but not always certain — a measured 3-way model choice scored 0.43, while a clear 2-way split scored 0.9997. Default 0.60.
Decision timeout (ms) a hung decision endpoint must never park a chat request; on timeout the heuristics serve. d3-turbo answered a small state in ~790ms.
Models the router may use
none checked = every chat model is routable. This set also bounds what the DECISION MODEL may pick: it is offered only the floor..ceiling window already filtered by this allowlist and endpoint health, and an answer naming anything outside it is discarded.

Max prompt chars hard cap on the RENDERED prompt — longer renders truncate (server accepts 200–60000)
Route the default model
Off (the default): auto keeps its documented meaning — the profile-order budget cascade, never consulting the router. On: auto is offered to the router exactly like routing. This is a different axis from the decision model above: that picks who decides, this picks which requests get decided. The explicit routing / routing__<model> names route regardless. Requires the calling key's profile routing_policy to be shadow or active.
Sticky routing
Off (the default). On: once a conversation has been served by a routed model, later turns may escalate above it but never fall below — so a thread that opened with a trivial turn cannot pin later hard work to the cheap model. The floor is re-checked every turn against the live candidate window and the key's allowlist; a model that leaves either is ignored. Independent of auto-demand-aware, which keeps its own separate sticky head.
Sticky idle reset seconds of inactivity after which a conversation forgets its floor and re-decides from scratch. Without it a long thread climbs monotonically to the ceiling. 0 = never reset (climb forever).

      
The decision model (vllm-sr / d3-turbo) IS called on routed requests: shadow records its pick without serving it, active serves it. Routing engages only when a request names routing / routing__<model> (or auto, when route the default model is ticked) AND the calling key’s profile routing_policy is shadow or active.
