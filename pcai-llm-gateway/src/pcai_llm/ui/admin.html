SSO self-mint default profile

Every key a user mints via Sign in with SSO gets this tenant's profile. On mint and on every rotate, two things happen: the profile's budgets, MCP grants and rate-limit presets are stamped onto the key row, and the user row is bound to the profile when it has none. Scopes stay the fixed least-privilege grant; profiles never widen them.

  • The mint's tenant is the deployment's tokenShadowTenantId. Clearing the profile returns mints to the bare grant (60 rpm · 100k tpm, no budgets or grants).
  • Edit the profile itself under Profiles.
  • Users who signed in before this setting existed have no profile. Bind existing users backfills them — idempotent, and a user placed by hand is never re-scoped. Until then their keys carry the stamped presets, but cascade ordering, routing, off-peak and agents ignore the profile.

Mint an enrollment code

Self-service key issuance — the code is the credential.

The plaintext code is returned once at mint time (only its SHA-256 hash is stored). Redeem at the chat console via Have an invite code?. Budget (tokens and/or USD per period) is the enrollment's team envelope — a HARD cap on the whole team; per-key allocations must fit inside it. With overflow ON (default) the unallocated remainder is a shared pool keys may draw on. Leave BOTH budget fields blank for an UNCAPPED team — the envelope then says "no cap" on the team console while the per-key allocations (profile presets, or what the leader hands out) still apply; there is no way to add a cap afterwards except by approving a top-up, so set it here if the team should be bounded.

Budget top-up requests

A team leader who has spent the enrollment's available pool can ask for a bigger envelope from /team_leader. Approving raises the cap — the total stays admin-only, and a leader can never approve their own ask. The amount is added to the current cap in one transaction, so a double-click is a 409 and never doubles a budget.

Session memory distiller

Quiet conversations are distilled into each key's RAG memory dataset.

—
  • One canonical pipeline replaces the per-harness distillers (DSH plugin, opencode agent, OWUI filter).
  • A key with no memory feature attached — no enabled mm-rag registry row, or no stamped dataset pair — is inert: the surface answers 200 with ok=false/inert=true and nothing runs.
  • Off-peak-only gates the scheduled sweep. An explicit distill call always runs.

Model routing — how a routed request picks its model

—
Runtime enabled
Also requires the env flag PCAI_LLM_ROUTING_ENABLED, which owns the route mount.
Decision mode
  • off — the heuristics pick the model.
  • shadow — the model is asked and its pick recorded, the heuristics still serve.
  • active — the model's pick serves when it clears the confidence floor and lands inside the candidate window.
Decision model
The pool asked to choose. Empty = heuristics only.
Confidence floor
Below this the model is treated as abstaining and the heuristics serve.
Switch margin
  • A challenger must beat the current model by this much before the router pays a switch.
  • A switch re-prefills the whole context on the new model.
  • 0 = the first pick wins, 1 = never switch.
Decision timeout (ms)
On timeout the heuristics serve, so a hung endpoint cannot park a request.
Route the default model
Off: auto keeps the profile-order cascade. routing and routing__<model> always route.
Sticky routing
A thread may escalate, but never falls below the model that already served it.
Sticky idle reset
Seconds of inactivity before a conversation forgets its floor. 0 = never.

Model cards — what each model is for

Tick a model to offer it to the router. Its description becomes that option's text in the routing question, so this is the only place the router learns what a model is good at. Live load, cost and image support are appended to each option automatically; a {{token}} in a description replaces the matching one.

Tick every model to mean no restriction (any chat model is routable). Ticking none is refused: on the wire an empty set means no restriction, so an empty form would save the opposite of "route to nothing".
